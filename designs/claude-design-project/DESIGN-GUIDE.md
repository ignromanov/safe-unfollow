# SafeUnfollow — Design Guide

Companion to `README.md` (which is generated by the code sync and lists the component/token
inventory). This file holds the judgment: what the product is, how it talks, and how it looks.

Sources: `github.com/ignromanov/safe-unfollow` (public app, MIT) and
`github.com/ignromanov/safe-unfollow-ai` (private product/strategy artifacts, `.claude/`:
`product.md`, `constitution.md`, `WIZARD_STYLE_DIFF.md`, `mobile-optimization-summary.md`,
and the advisory skill definitions under `skills/conclave-*`).

## 1. Product context

**SafeUnfollow.app** — an Instagram relationship analyzer that runs entirely in the browser.
The user downloads their official Instagram data export (a ZIP from Meta Accounts Center),
drops it on the page, and sees who unfollowed them, who does not follow back, and who is mutual.
Nothing is uploaded. There is no login, no account, no server.

Three pillars, from the project constitution:

| Pillar | Meaning |
|---|---|
| Privacy-first | "We can't leak your data if we never have it." IndexedDB only, no telemetry on user data. |
| The analysis is free | Every badge, filter and account, at any export size. No subscription, no account, MIT licensed. The one paid thing is a $7 file — see the trust budget below. |
| Performance at scale | 1M+ accounts, filter under 5ms, virtualized list at 60fps. |

Slogan: *"The only unfollow tracker that works even if we shut down."*

**Audience**: 85% mobile. Top markets are the US and Indonesia (effectively tied), then India
and the Philippines. Locale share: en 63.6%, id 26.8%, then ru/es/fr/pt/de/tr in low single
digits. 80% of users have fewer than 3,000 accounts; 6% are influencers with 10,000+.

**Positioning against paid trackers**: they require an Instagram login (ban risk), store your
follower history on their servers, charge $5–10/month, and cap at 10k–100k accounts.
Every design decision should make the opposite of each of those legible at a glance.

**Surfaces**: one React SPA (hero → guide wizard → upload → results), a Jekyll docs site,
and an SEO/OG image endpoint. There is no dashboard, no admin, no logged-in state.

### What the constitution costs the design

The seven principles are not background reading — each removes a pattern most products lean on.

| Principle | What it forbids in the UI |
|---|---|
| Privacy-first | No avatars, no profile photos, no follower thumbnails — the export contains no images and nothing may be fetched. Every avatar slot is a `user` glyph on a zinc tile. |
| Zero-backend | No account menu, no settings sync, no "saved views", no share links. State that survives a reload lives in IndexedDB on that one device. |
| Performance at scale | The account list is virtualized; never design a layout that requires measuring all rows (no masonry, no group-by headers with counts computed on render). Filter chips show counts because bitsets make them free. |
| State discipline | No optimistic cross-screen previews — the results screen owns the data, other screens get counts at most. |
| Accessibility | WCAG AA 4.5:1 minimum, full keyboard path, ARIA on every stateful control. Colour alone never carries a badge's meaning — the label is always spelled out. |
| Open source | Nothing is obfuscated or gated. If a feature looks premium, it is a paid *export*, never a paywalled view. |

Design philosophy inherited verbatim: *YAGNI · Privacy > Features · Simplicity > Cleverness ·
Performance > Convenience.*

**RTL matters** — Arabic is a shipped locale. Layout uses logical properties (`ps-`, `pe-`,
`text-start`, `start-3`), and `[dir="rtl"]` resets display letter-spacing to 0.

## 2. Content fundamentals

**Voice**: plain, concrete, slightly blunt. It sells with facts, not adjectives. Never breezy
marketing-speak, never apologetic.

**Person**: second person to the user ("your data", "you analyzed 8,930 accounts"), first person
plural for the project ("we value your trust", "we could not find this license key"). Never "I".

**Sentence shape**: short declaratives. Fragments are fine in micro-copy. Em dashes carry the
qualifier: *"Find out who unfollowed you on Instagram — free, no login required."*

**The bullet separator is `•`**, used to chain trust claims:
`Free Analysis • No Limits` · `No Password • No Account Risk` · `100% Private • Local Analysis`
and to join metadata: `sample-data.json • 8,930 Total`.

**Numbers are the argument.** Real figures appear everywhere and are always locale-formatted:
`1,000,000+ accounts`, `V1.6`, `<5ms`, `26% of uploads fail`. Never round a real number up for
effect and never invent one.

**Casing**:
- Headlines: sentence case with proper nouns — *"Check Instagram Unfollowers Without Logging In"*.
- Buttons: title case — *Check Unfollowers Free*, *Try with Sample*, *Buy a Coffee*.
- Micro-labels, stat labels, footer links, badges: ALL CAPS with `tracking-widest` and `font-black`.
- Badge labels themselves are written sentence case in the data (*Not following back*) and
  uppercased by CSS.

**Errors name the cause and the fix, in that order**: *"That does not look like a license key.
Check the key in your purchase email."* No "Oops", no "Something went wrong", no exclamation
marks outside the one deliberate wizard warning (*"Critical step!"*).

**Money copy is disarming, never pressuring**: *"You analyzed 8,930 accounts. It was free."* ·
*"If this saved you time, a coffee keeps it going."* · *"Ads and the odd recommendation keep
this running — your export is never part of it."* Dismissals are gentle: *Not now*, *Maybe later*.

⚠ This line used to open with *"This tool has no ads and no investors."* It was true when it
was written and has been false since 2026-07-27, which is exactly why it is quoted here rather
than deleted: it is the shape to avoid, not a phrasing preference. What survives the change is
the narrow claim — the export never leaves the browser, so no ad, network or processor can be
targeting it — and that is stronger than the blanket one because it is still true.

**No emoji in product UI.** (Emoji appear in internal docs only.) No exclamation-heavy hype,
no fake urgency in the core flow — the one urgency line lives in the affiliate rescue banner
and is clearly labelled as a recommendation with an affiliate disclosure.

**Always disclose**: affiliate blocks carry *"Hand-picked tools we recommend. Affiliate links
fund free updates — no cost to you."* Ad slots carry the label *Advertisement*.

### The trust budget

The project runs two deliberately opposed advisory seats: growth (*"reach and revenue are one
funnel"*) and privacy-trust (*"assume the leak until proven impossible"*). That tension is
supposed to stay visible in the design rather than be resolved in growth's favour.

Practical rules for any earning surface — ad slot, affiliate rescue plan, donation card, the
$7 export unlock:

- **Every monetized surface is priced in trust and must say so.** Disclosure sits inside the
  block, at the same reading weight as the offer, never in a footnote or a tooltip.
- **It never sits in the critical path.** Upload, parse and results render fully without it;
  monetized blocks are inserted between sections or after the result, and all of them are
  dismissible (*Not now*, *Maybe later*) with the dismissal remembered.
- **It never mimics product chrome.** An affiliate card reads as a recommendation card, not as
  a stat tile or a filter chip.
- **Paid means paid artifact, not paid view.** The export paywall sells a file — the analysis
  itself stays free and complete. Copy names the competitor's price and undercuts it once,
  factually: *"Similar trackers charge $5–10 a month… This is $7, once, for the file itself."*
- **No dark patterns**: no countdown timers on core flows, no pre-checked consent, no fake
  scarcity. The one urgency line lives inside the rescue banner and is visibly an opinion.

### Messaging that is known to work

Five claims carry the acquisition funnel and should stay recognisable wherever they appear —
hero, OG image, docs, meta description:

| Message | Why |
|---|---|
| "No login required" | Users fear Instagram bans; 50–100% CTR on *without login* queries |
| "Works with your Instagram ZIP file" | Names the safe, official method |
| "Handles 1,000,000+ accounts" | The influencer segment's hard requirement |
| "100% local, private" | The core differentiator |
| "Free analysis, open source" | Trust through auditability |

They are stated as facts and never softened into adjectives (*"blazing fast"*, *"secure"*).

⚠ The fifth one used to read *"Free forever"* and must not be written that way again. Since
2026-07-27 the product carries ads, one affiliate placement and a $7 export unlock, so an
unqualified *free* is false — and `src/__tests__/docs/monetization-claims.test.ts` bans that
shape of claim in the docs. That guard reads Markdown, not generated designs: nothing will
turn red if a design ships the sentence. The narrow claim is the true one and the one that
does the work anyway — *the analysis is free*, and *the Instagram export never leaves the
browser*.

**The biggest known UX failure is a copy problem**: 26% of uploads fail, and 48% of those are
users who picked HTML instead of JSON in Meta's export dialog. That is why step 6 of the guide
is the only step marked *Critical*, why its warning uses the amber system rather than
destructive red, and why the upload screen repeats the JSON requirement. Any redesign of the
guide must keep that step loud.

## 3. Visual foundations

### Color

Everything is authored in **OKLCH**, never hex, for perceptual consistency across light and dark.
The palette is one hue family — a violet-blue base at 264° — extended by two neighbours:

- `--primary` `oklch(0.6 0.18 264)` — indigo. Every CTA, active state, focus ring, link hover.
- `--accent` `oklch(0.65 0.22 285)` — violet. The middle gradient stop; secondary icon accents.
- `--secondary` `oklch(0.65 0.2 340)` — magenta. Gradient end stop. Rarely used as a solid fill.
- `--destructive` `oklch(0.55 0.22 25)` — used with Tailwind `rose-500` for delete and data-loss.

Surfaces are near-neutral with a 264° tint carried through: background `oklch(0.99 0.005 264)`,
card pure white, muted `oklch(0.96 0.005 264)`, border `oklch(0.92 0.01 264)`.
Dark mode inverts to background `oklch(0.12 0.01 264)` / card `oklch(0.18 0.015 264)` and
*lightens* the brand hues (primary drops chroma to 0.16, accent rises in lightness to 0.7)
so they stay readable on dark. Toggle is a three-way cycle: system → light → dark.

Semantic accents come from the Tailwind scale, one hue per meaning, used consistently:
emerald = safe/local, rose = loss/destructive, indigo = mutual, amber = warning/caution,
blue = following, pink = close friends.

**The badge palette is the product's signature.** Eleven relationship types, each rendered as a
12% tint background, a 20% border, and the solid hue as text. Unfollowed is the loud one —
15% background, 30% border, `font-bold`. Never invent a twelfth badge colour; see
`foundations/color-badges.card.html` for the exact values.

### Type

Two families, both variable:

- **Plus Jakarta Sans** (`.font-display`) — every headline, stat number, username, and logo
  wordmark. Weights 700–900. Always `letter-spacing: -0.04em`, `line-height: 1.15`.
  Hero runs `text-4xl` on mobile to `text-8xl` on large screens.
- **Inter** — body, UI, form fields. Body line-height is `1.625`, weight 500 for lead paragraphs.
  Antialiased, `text-rendering: optimizeLegibility`.

A third register does a lot of work: the **uppercase micro-label** — 12px, `font-black`,
`tracking-widest`. It marks stat labels, filter titles, footer links, badges, and section
eyebrows. When in doubt about a small label, it is probably this.

Mono is the system stack, only for filenames, license keys and timings.

### Shape and depth

`--radius` is `0.75rem`, but the app lives at the large end of the scale: buttons and filter
chips at `rounded-2xl`, stat cards `rounded-3xl`, panels and the account list `rounded-4xl`
(2rem), the badge pill at `rounded-lg`, the version pill fully round. Avatars and the logo tile
are `rounded-2xl` squircles, never circles — the only circles in the product are the delete-
confirmation icon well and the live-status dot.

Elevation is restrained: cards rest at `shadow-sm` with a 1px border and lift to `shadow-xl` on
hover. The only heavy shadow is on primary CTAs — `shadow-2xl shadow-primary/30`, a coloured
glow rather than a grey drop. The wizard footer uses an upward shadow
`0 -10px 20px oklch(0 0 0 / 0.03)`.

Borders do the structural work. Almost every surface is `border border-border` on `bg-card`;
separators inside lists are `border-b border-border last:border-0`.

### Gradient

One gradient, three stops, two forms:

- `.bg-gradient-brand` — `135deg`, 264° → 285° → 340°. Fills the logo tile and the upload well.
- `.text-gradient` — `to right`, same stops, clipped to text. Reserved for **one highlighted
  phrase per headline** ("Instagram Unfollowers"). Never a whole heading, never body copy.

There is no gradient anywhere else. Backgrounds are flat colour — no meshes, no blurred blobs,
no photographic hero.

### Motion

Transitions are `transition-all` at the default duration; the accordion runs 0.2s ease-out.

- **Hover**: buttons `scale-[1.02]` or `scale-105`; cards `hover:shadow-xl hover:-translate-y-1`;
  icons inside a `group` `scale-110`; the logo tile `scale-110 rotate-6`; the footer logo `rotate-12`;
  arrow icons `translate-x-1`.
- **Press**: `active:scale-95` on every primary action. This is the one universal press signal.
- **Entrances**: `animate-in fade-in duration-700` on the hero, `zoom-in-95 duration-300` on the
  wizard, `slide-in-from-top-2 duration-300` on disclosure.
- **Ambient**: exactly two loops — the `animate-ping` dot in the version pill and the pulsing
  heart in the footer.
- Everything above is disabled under `prefers-reduced-motion`, and all hover transforms and
  shadows are reset under `@media (hover: none)` so they do not stick on touch.

### Transparency and blur

Blur is used twice: the sticky header above `md` (`bg-card/80 backdrop-blur-md`) and the hero
version pill. Elsewhere, translucency appears as tint fills — `bg-primary/10`, `bg-blue-500/10`,
`bg-[oklch(0.5_0_0_/_0.05)]` for neutral hover. Overlays are `bg-background/80` with a light blur.

### Layout

Centered `container` with 2rem padding, capped at 1400px. Hero content is `max-w-5xl`, results
`max-w-7xl`, prose `max-w-2xl`. The header is sticky, `h-16` on mobile / `h-20` desktop, at
`z-[80]`; the wizard sits above it at `z-[100]`. The filter sidebar is `md:w-72` and
`sticky top-24`.

Mobile-first is not a slogan here — 85% of traffic is mobile. Touch targets are ≥44px
(`py-3` icon buttons on mobile collapse to `py-2` with a visible label on desktop), filter
chips are a 2-column grid on mobile and a 1-column sidebar on desktop, and the badge row inside
an account item scrolls horizontally with `no-scrollbar`.

**The mobile contract**, from the project's own optimization pass:

| Element | Mobile | Desktop |
|---|---|---|
| Filter chip | 44px min | 32px |
| Search input | 48px | 40px |
| Primary button | 48px min, `w-full` | auto width |
| Account row | 68px | 60px |
| Accordion trigger | 56px min | 56px |
| Clear / secondary | 36–40px min | 32px |

The pattern set is small and should be reused rather than reinvented: base styles are the
mobile case with no prefix and desktop overrides ride on `sm:`/`md:`/`lg:`; layouts go
`flex-col sm:flex-row`; buttons go `w-full sm:w-auto`; secondary words are dropped with
`hidden sm:inline` rather than truncated (the header's *Results* label, the search bar's
*accounts*). iOS home-indicator clearance uses a safe-area bottom pad on the scrolling shell.

*(The optimization report those figures come from predates the current component names — it
describes `HeroStep`/`JourneyContainer`, which are now `Hero`/`Layout`. The numbers still hold;
the file paths in it do not.)*

### Accessibility

WCAG AA is a constitutional requirement, not a polish pass.

- 4.5:1 minimum contrast. The 12%-tint badges pair with a solid-hue label specifically to clear
  it; do not lighten the text to match the fill.
- Badge meaning is always written out, never carried by colour alone.
- Stateful controls announce state: filter chips and stat tiles are `aria-pressed`, account rows
  are `role="article"` with `aria-posinset`/`aria-setsize` for the virtualized list, search
  results are announced through an `aria-live="polite"` region.
- Every icon-only control has an `aria-label`; decorative icons are `aria-hidden`.
- Links that open a new tab append a screen-reader-only "(opens in new tab)".
- Focus is the `--ring` colour at a 3px ring; never remove the outline.
- All motion is gated on `prefers-reduced-motion`.

### Imagery

The product ships almost no decorative imagery. What exists is functional: 8 wizard screenshot
posters (`public/wizard/step-N-600w-poster.jpg`, `aspect-video`, `rounded-4xl`, hover
`scale-105` over 700ms) and marketing screenshots in `assets/`. No illustration style, no stock
photography, no hand-drawn elements. Where an image is missing, the slot is a flat
`bg-[oklch(0.5_0_0_/_0.05)]` block.

## 4. Iconography

**Lucide** (`lucide-react`), exclusively. No second icon set, no emoji, no unicode glyphs
standing in for icons.

- Sizes: 14 (footer links, filter meta) · 18 (filter chips, header actions) · 20–22 (buttons,
  logo tile) · 24 (feature cards, avatars) · 28–34 (empty states, upload well).
- Stroke width is the Lucide default 2, raised to 2.5 for the ShieldCheck in the logo and the
  upload icon.
- Colour comes from a Tailwind `text-*` class on the icon, never a `fill` — the one exception is
  the footer heart and close-friend badge, which use `fill-current`.
- Each badge type has a fixed icon: Followers `user-plus`, Following `users`, Mutuals `heart`,
  Not following back `trending-down`, Not followed back `ghost`, Unfollowed `circle-x`,
  Pending `clock`, Restricted `circle-alert`, Close friend `heart`, Dismissed `circle-x`.

The **logo** is a rounded-rectangle (rx 96 of 512) filled with the brand gradient, with the
Lucide `shield-check` glyph knocked out in white — see `assets/logo.svg`. It is inlined as SVG in
the app so CSS can animate it. Never recolour it, never place it on a coloured tile.
The wordmark is `SafeUnfollow` in display extrabold with `.app` in `--primary`.

Icons in `foundations/icons.card.html` are the actual set the product uses, loaded from the
Lucide CDN at the pinned version.

### Intentional additions

Nothing was invented. The foundations cards, the catalog cards and the UI kit are all
recreations of values read from the two repositories. The one substitution: the Lucide icon set
is loaded from the CDN at a pinned version rather than vendored, because the app consumes it as
a React package rather than as asset files.
